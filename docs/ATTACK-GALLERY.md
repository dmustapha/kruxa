## Not in the gallery

- **CO4-A3**: Solana devnet mintTo on the genesis mint. Needs a Solana devnet program; the gallery is NEAR sandbox only.
- **CO4-A10**: tampered evidence file against verify.sh. Offline verify.sh tamper is a separate deliverable (scripts/verify.sh --tamper-all), not a contract attack.
- **CO4-A13**: hijacked agent against the vault. Cut with the vault (CHANGE-ORDER-6 E-2).
- **REDIRECT-VIA-SETTER**: call a method that changes the stream or payout recipient after open. No such method exists in core or market: the recipient is fixed at create_trial / pool open. A04 and M02 attack the only reachable paths and assert the recipient is unchanged.
- **CORE-PLATFORM-WITHDRAW**: non-owner platform withdraw on core. Core has no platform-withdraw method (launch fee goes to a fixed treasury via permissionless pay_launch_fee). The market has withdraw_platform and M04 attacks it.
- **CORE-SANDWICH**: sandwich on core. Core has no AMM. Sandwich and min_out are market attacks (M06).
- **GENESIS-F0-SIGN**: F0 genesis (MPC child key) attacks and Solana-side checks. sign_genesis (Task 4.6) is not built; NEAR cannot see Solana, so confirm_genesis is a signed claim audited by verify.sh (detected, not prevented). The gallery attacks only the contract-side state machine, leaves and plan.
- **INSTANT-REAL-FACTORY**: launcher against the real token factory (token.primitives.testnet). The sandbox factory is a mock that creates nothing. The real factory runs only on testnet: see evidence/instant-testnet (factory behaviour, registration with 0.00125 NEAR, failed-creation refund).
- **INSTANT-SEVEN-DAY-CLOCKS**: freeze auto-expiry and the 7-day cap timelock by waiting. Both are 7 real days even on the demo profile (only the launcher's day unit is 10 s). A sandbox wait would need about 2 million blocks. I36 and I38 assert the bound with the pure kruxa_logic functions and the queued effective_at instead.
- **INSTANT-ANNOUNCED-OPEN**: trade_from_ns announced open. Not in market 1.1.0 (cut first in CO-7); nothing to attack.

## Reproduce

`make attack-gallery` (exit 0 only if every attack was refused, had no effect, or is a disclosed bound, and invariants held).
`make attack-gallery-red` flips one attack to succeed on purpose and must exit non-zero. The test-only switch
`KRUXA_GALLERY_SABOTAGE=A11` makes the first admin call of A11 come from the owner (who is allowed), so that attack
"succeeds"; the record shows SUCCEEDED_UNEXPECTEDLY and the script exits 1. The committed proof is in
`evidence/attack-gallery/red-mode/`.

attacks against the core once it is deployed on testnet, and label those hashes TESTNET so they can be looked up on an explorer.
