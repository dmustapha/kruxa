| N-04 | launcher review N-04 | Token-leg retry depends on the launch token refunding the repeat storage_deposit (0.00125 NEAR) | DISCLOSED, bounded (sandbox measured; real factory token repeat-refund PROBED on testnet 2026-11-10: refunded) | Sandbox test tests/tests/instant_token_leg_storage.rs, record evidence/instant-n04/storage-deposit-retry.json. Every token-leg attempt attaches 0.00125 NEAR of the launcher's own balance to storage_deposit(market). Against a NEP-145 token that refunds a repeat deposit, a retry changes the launcher's NEAR balance by 0 (measured -1e-24 NEAR, the one attached yocto). Against a token that KEEPS the deposit, each retry costs the launcher exactly 0.00125 NEAR (3 of 3 retries measured). The first attempt always pays the real registration once. Worst case, exact: a retry exists only after a refused token leg (market paused or misconfigured, token ft_transfer_call refused), and open_instant is permissionless with no cooldown, so while refusals last anyone can repeat it; each repeat moves 0.00125 NEAR out of the launcher's pooled NEAR (the per-launch deposits that fund record storage, the market storage forward and refunds), about 800 retries per 1 NEAR, until the launcher balance reaches its storage-staking floor. The sender burns about 0.00135 NEAR of gas per retry against the cheapest possible receiver (stub market, about 13.5 Tgas) and more against the real market, so the drain costs the attacker at least as much as it takes: griefing at cost parity, never a profit. Real testnet factory token probe (round 2, evidence/testnet-core3/real-factory-probe.json): on kxr2g110.token.primitives.testnet a first storage_deposit(registration_only) for treasury.kxi-root-1108.testnet (tx 683Ai8Yr9k1GVVMZynFpn2sQsf8N8w6D2UPxGsustVGU) registered it (storage_balance_of total 0.00125 NEAR), and a second identical deposit (tx BveMgNnxG4B1BtiJSyswsHQCCYiWpeQPykRJX5Krd1d5) logged 'The account is already registered, refunding the deposit' and sent the 0.00125 NEAR back to the caller (net cost of both calls to the caller about 0.0019 NEAR: one registration plus gas). So the testnet factory token refunds a repeat deposit, as NEP-145 requires; the retry cost for the launcher is gas only. Not proven: the same for a mainnet factory token (read-only reasoning only, same contract family). Its bounds are min 0.00125 = max 0.00125 NEAR (docs/runbooks/instant-testnet.md), so NEP-145 requires the refund; Mitigation if it matters: attach the registration deposit once per launch (a flag like market_prepared), which needs a launcher change and a redeploy. |
