# REQ-1: what the genesis relayer and signer need from core (A to A2)

From: workstream A (core, Task 4.4). To: A2 (relayer, `tools/squads`, `tools/sas`, `scripts/genesis-*.sh`). Status: core side BUILT in `contracts/core/src/genesis.rs`; the logic lives in `crates/kruxa-logic/src/genesis.rs` (pure, reusable by Rust tools; the TypeScript relayer must match it with golden vectors).

## Account and role
The owner calls `set_genesis_relayer(account)` once. That account (a function-call key limited to `commit_genesis`, `build_root_page`, `confirm_genesis`, `abort_genesis`, `attest_log_append`) is the only caller of those methods. `abort_genesis` also accepts the guardian. `pause_genesis` (owner or guardian) stops commit, pages and confirm; `resume_genesis` is owner only. All 32-byte values cross the JSON boundary as 64 lowercase hex characters; u64 values as decimal strings.

## Call sequence (launch must be Passed, every position settled, `sweep_residue` done; otherwise `R_GENESIS_STATE`)
1. `solana_allocations_page(launch_id, from_seq, limit<=50)` (view) returns `[{pubkey, amount}]` for Solana buyers. Sort ascending by pubkey bytes.
2. Generate `G` (F1) and call `commit_genesis(launch_id, g_pub)`. One-shot (`R_GENESIS_ALREADY`, also after an abort). F0: `g_pub` must equal the `mint_pubkey_f0` named in the plan at `create_trial` (`R_GENESIS_ARG` otherwise). The contract stores `mint_address = sha256(g_pub || ascii(launch_id) || Tokenkeg bytes)` (createWithSeed, no private key exists) and the expected leaf count and total.
3. `build_root_page(launch_id, leaves: [[pubkey_hex, amount_string], ...])`, at most 25 per page, strictly ascending across all pages, each equal to the Solana Position (`R_GENESIS_ORDER`, `R_GENESIS_LEAF`). When the last expected leaf lands the contract fixes `merkle_root` and `genesis_spec_hash` and emits `genesis_committed`. Zero Solana buyers: the root is 32 zero bytes and `commit_genesis` finishes at once.
4. Compile the two transactions from the spec: read `get_genesis_spec(launch_id)` (base64 of borsh `GenesisSpec`), check `sha256(bytes) == get_genesis(launch_id).genesis_spec_hash`, then run the public compiler with a blockhash and a price.
5. After both transactions land: `confirm_genesis(launch_id, mint_hex, sigs[1..4], slot, ceremony_hash_hex)`; `mint_hex` must equal the committed `mint_address`.
6. Optional: `attest_log_append(launch_id, attestation_hash_hex)` (needs Confirmed, at most 64).
On any failure before step 5: `abort_genesis(launch_id, reason<=200 bytes)`.

## What the relayer must conform to (single source: `crates/kruxa-logic/src/genesis.rs`)
- `GenesisSpec` borsh field order and `GENESIS_COMPILER_VERSION = "gs-compiler/1.0.0"`. Golden vector to be generated by `kruxa-sim` once A2 starts the TypeScript compiler (core test `full_ceremony_commit_pages_confirm` shows the view/decode path).
- Leaf: `sha256(0x00 || sha256(claimant || unlocked_le_u64 || locked_le_u64))` with `locked = 0`; node: `sha256(0x01 || min(a,b) || max(a,b))`; odd node carried up unchanged. **Both are UNVERIFIED against the deployed Jito distributor until test T-D1 reads its IDL.** If T-D1 shows another layout, change `leaf_hash` and `node_hash` in the logic crate only and re-run the genesis tests.
- Cluster hash constants (base58, ASSUMED from memory, A2 to confirm with `getGenesisHash`): mainnet `5eykt4UsFv8P8NJdTREpY1vzqKqZKvdpKuc147dw2N9d`, devnet `EtWTRABZaYq6iMfeYKouRu166VU2xqa1wcaWoxPkrZBG`. The profile `mainnet` selects the first, any other profile the second.
- Buckets in the spec: DISTRIBUTOR = sum of leaf amounts, plus LP_MIRROR only if the plan sets `lp_mirror_to_solana` (default false, see DECISION-NEEDED in the core report). Bucket owners are NOT committed: the public compiler derives them from `reserve_squads_multisig_hash`, `reserve_vault_index`, the Jito program id and the distributor PDA.
- Leaf amount is `tokens_entitled + bonus_entitled` of the Position (the backer bonus has no separate locked part yet; DECISION-NEEDED if the distributor must receive a locked part).

## Events the relayer and indexer can rely on (NEP-297, standard `kruxa`)
`genesis_relayer_set`, `genesis_paused`, `genesis_resumed`, `genesis_committed {launch_id, g_pub, mint, merkle_root, genesis_spec_hash, leaf_count, max_total_claim, mode}`, `genesis_confirmed {launch_id, mint, sigs, slot, ceremony_hash}`, `genesis_aborted {launch_id, by, reason}`, `attest_log {launch_id, attestation_hash}`.

## Not built here
`sign_genesis` and the F0 policy gate (Task 4.6), the TypeScript compiler, `abort` recovery for creators and backers (Wave 6b), invariant L7' (`near_circulating + sol_mint_supply == total`) as a view.
